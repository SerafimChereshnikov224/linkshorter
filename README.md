# LinkShorter

Консольный сервис сокращения ссылок: уникальные короткие ссылки, лимит переходов,
время жизни (TTL) с автоудалением, уведомления и идентификация пользователя по UUID
без авторизации.

## Возможности

- Сокращение длинных URL в короткие ссылки вида `sho.rt/aB3dE9x`.
- Разные пользователи получают разные короткие ссылки на один и тот же URL.
- Лимит переходов: после исчерпания ссылка блокируется и владелец получает уведомление.
- TTL задаётся системой в конфигурации; протухшие ссылки удаляются автоматически.
- Уведомления об исчерпании лимита и истечении срока жизни.
- UUID пользователя создаётся при первом `create` и сохраняется между запусками.
- Редактирование и удаление ссылки доступны только её создателю.
- Несколько ссылок у одного пользователя и мультипользовательский режим (`user <uuid>`).
- Переход по короткой ссылке открывает исходный URL в браузере (`Desktop.browse`).

## Требования

- JDK 21+
- Maven 3.9+

## Сборка и запуск

```bash
mvn clean package
java -jar target/linkshorter.jar
```

Или из Windows:

```bat
scripts\run.cmd
```

Приложение работает в интерактивном режиме (REPL) или выполняет одну команду и выходит:

```bash
java -jar target/linkshorter.jar create https://www.baeldung.com/java-9-http-client --limit 5
```

## Команды

| Команда | Описание |
| --- | --- |
| `create <url> [--limit N]` | Сократить ссылку; `N` — максимальное число переходов |
| `open <code>` | Перейти по короткой ссылке (открывает браузер) |
| `list` | Показать только свои ссылки со статусом и остатком переходов |
| `show <code>` | Подробности ссылки |
| `limit <code> <N\|none>` | Изменить лимит переходов (`none` — без ограничения) |
| `delete <code>` | Удалить ссылку |
| `notifications` | Показать уведомления и отметить их прочитанными |
| `whoami` | Показать текущий UUID |
| `user <uuid>` | Войти под указанным UUID |
| `help` | Список команд и примеры |
| `exit` | Выход |

Короткий код можно передавать как целиком (`sho.rt/aB3dE9x`), так и без префикса (`aB3dE9x`).

## Конфигурация

Параметры читаются из `application.properties` в рабочем каталоге (перекрывает встроенный
конфиг из classpath). Любой параметр можно переопределить system property:

```bash
java -Dlink.ttl.minutes=5 -jar target/linkshorter.jar
```

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `link.ttl.minutes` | `1440` | Время жизни ссылки в минутах (задаётся системой) |
| `link.max-visits.default` | `100` | Лимит переходов, если `--limit` не указан |
| `link.max-visits.max` | `1000000` | Верхняя граница допустимого лимита |
| `storage.dir` | `data` | Каталог для `links.json`, `notifications.json`, `session.json` |
| `shortlink.prefix` | `sho.rt/` | Префикс отображения коротких ссылок |

Для проверки TTL удобно поставить `link.ttl.minutes=1`.

## Как это работает

- **Короткий код** — 7 символов Base62 (`SecureRandom`), уникальность проверяется по хранилищу;
  при коллизии код генерируется заново. Поэтому один и тот же URL у разных пользователей
  получает разные коды.
- **UUID** — генерируется при первом `create`, хранится в `data/session.json` и используется
  для проверки прав на `show`, `limit`, `delete` и для фильтрации `list`.
- **Лимит переходов** — счётчик `visits` увеличивается при каждом `open`; при `visits == maxVisits`
  ссылка блокируется, а владельцу добавляется уведомление (однократно).
- **TTL и автоудаление** — `expiresAt = createdAt + link.ttl.minutes`. Протухшие ссылки удаляются
  при старте приложения и перед обработкой каждой команды; владельцу создаётся уведомление.
  Попытка открыть протухшую ссылку также приводит к её удалению.
- **Уведомления** — хранятся в `data/notifications.json`, адресованы владельцу и отмечаются
  прочитанными после команды `notifications`.

## Архитектура

```
ru.linkshorter
├── App                  точка входа, сборка зависимостей
├── config               AppConfig — чтение и валидация application.properties
├── core
│   ├── model            Link, Notification, статусы
│   ├── port             интерфейсы репозиториев и BrowserLauncher
│   ├── service          LinkService, NotificationService, UrlValidator, ShortCodeGenerator
│   └── exception        доменные исключения
├── infra
│   ├── storage          JSON-репозитории (Link, Notification, Session)
│   └── browser          DesktopBrowserLauncher
└── ui.cli               Cli — парсинг команд и вывод
```

Слои разделены интерфейсами (`core.port`), зависимости передаются через конструкторы.
`core` не знает про файлы и `java.awt`.

## Тестирование

```bash
mvn test
```

47 тестов (JUnit 5 + AssertJ):

- unit: валидация URL, генерация кодов, модель `Link`, `LinkService` (права, лимиты, TTL,
  уведомления), конфигурация;
- интеграционные: сохранение и восстановление JSON-хранилищ, сквозные сценарии CLI
  (`create → open → лимит → уведомление`, автоудаление по TTL, права владельца).

Линт/формат:

```bash
mvn spotless:check
mvn spotless:apply
```

## Ограничения

- Данные хранятся в JSON-файлах, без внешней БД.
- Открытие браузера доступно только в графической среде, где поддерживается `java.awt.Desktop`.
- Приложение однопользовательское по процессу: текущий UUID хранится в файле сессии.
